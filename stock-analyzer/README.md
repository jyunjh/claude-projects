# US Stock Analyzer / 米国株アナライザー

長期・ファンダメンタル重視・コントラリアンの投資哲学に基づく、ブラウザで動く米国株分析ダッシュボードです。
A browser-based US stock analysis dashboard built around a long-term, fundamental, contrarian philosophy.

## 特徴 / Features

- 📊 **銘柄分析ダッシュボード** — 主要財務指標を一覧表示
- 💰 **バリュエーション** — 株価 vs 推定適正価値
- 🔄 **コントラリアン・シグナル** — 市場センチメントとファンダメンタルの乖離を可視化
- 🎯 **重要ファクター (EPIC)** — 各銘柄の Critical Factors を影響度・発生確率で整理
- 🛡️✈️ **セクター特化分析** — セクター独自の市場環境と特化KPIで分析（**防衛** / **航空アフターマーケット** に対応）
- 📋 **グループ内 横比較** — 同セクター銘柄を一覧表で並べ、指標ごとに最良値を★でハイライト
- 📖 **見るべきポイント解説** — 各指標の見方を折りたたみで解説
- 🔄 **最新データ更新** — 2つの無料API (Finnhub + FMP) を併用して株価・指標を取得。互いの穴を埋め合い、取れない項目は `null` のまま（推測で埋めない）
- 🧑‍🏫 **メンター相談（AIチャット）** — 画面の分析を見ながら、熟練ファンドマネージャー役のClaudeにリアルタイムで相談
- ✅ **投資判断** — 上記を総合した BUY / HOLD / AVOID
- 🌐 **日本語 / English** ワンクリック切り替え
- 📱 **スマホ対応** — 縦持ちレイアウトに最適化。同じWi-Fiのスマホからも閲覧可（`--host 0.0.0.0`）

### メンター相談 / Mentor chat

ダッシュボード下部のチャットで、現在表示中の銘柄分析について AI に相談できます。AIは**長期・ファンダメンタル・コントラリアン**の投資哲学と添付フレームワーク（EPIC / バリュエーション相互チェック / TIER 等）に基づき、後輩アナリストを指導するように助言します。画面の数値（PER・乖離・重要ファクター等）を踏まえて回答します。

1. [Google AI Studio](https://aistudio.google.com/apikey) で **無料の Gemini APIキー** を取得（カード登録不要）
2. チャット下の「⚙️ AI設定」にキーを貼り付けて保存（localStorage に保存）
3. 質問を入力するか、サジェストをクリック → ストリーミングで回答

> 仕様: モデル `gemini-2.5-flash` / Gemini API をブラウザから直接ストリーミング呼び出し。無料枠（1日250回程度）で利用可能。学習用であり投資助言ではありません。

**自動フォールバック**: `gemini-2.5-flash` を優先利用し、無料枠の上限（HTTP 429）に達したらチャットに通知して `gemini-2.5-flash-lite`（1日約1,000回）へ自動切替。flash が回復したら自動で flash 優先に戻します（指数バックオフで無駄な再試行を抑制）。

### 最新データの取得 / Live data

**2つの無料APIを併用します。**どちらか一方のキーだけでも動きます。

| プロバイダ | 無料枠 | 担当 | キー取得 |
|---|---|---|---|
| **Finnhub**（優先） | 60call/分・日次上限なし | 株価（リアルタイム）・時価総額・PER・PBR・PSR・ROE・利益率・配当利回り・D/E・増収率 | [finnhub.io](https://finnhub.io/register) |
| **FMP**（補完） | 250call/日 | 株価チャート・日次終値フォールバック・EV/EBITDA・FCF利回り | [financialmodelingprep.com](https://site.financialmodelingprep.com/developer/docs) |

1. 上記でキーを取得
2. アプリ右上の「⚙️ API設定」に貼り付けて保存（ブラウザの localStorage に保存。1回だけ）
3. 「🔄 最新に更新」を押すと、表示中セクターの銘柄が最新値に更新されます

**なぜ併用するのか** — FMPの無料プランでは `quote` / `ratios-ttm` / `key-metrics-ttm` が
`HTTP 402 (Exclusive Endpoint = 有料プラン専用)` になります。一方 Finnhub の無料枠は
株価と基本ファンダメンタルズをカバーしますが、ローソク足は有料です。**互いの穴を埋め合う**構成です。

**値の優先順位** — Finnhub → FMP の順に取得し、**後から来たプロバイダは「空いている項目だけ」を埋めます**。
同じ項目を上書きすることはありません。どちらでも取れなかった項目は `null`（未取得）のままで、
推測値では埋めません。

**株価の出所を隠しません** — `quote`（リアルタイム）ではなく日次終値にフォールバックした場合、
株価の横に「終値 2026-09-02」バッジが出ます。AIメンターに渡す文脈にも同じ注記が入ります。

> 更新対象は市場データ（株価・バリュエーション指標）です。**適正価値・センチメント・重要ファクター**は、あなた自身の分析・推定値として保持されます（コントラリアン投資では、ここが腕の見せ所）。
> キーが無い／取得に失敗した場合は、自動的にサンプルデータで表示します。

**単位（実測で確認済み / 2026-09-06）** — Finnhub の `stock/metric` は
`marketCapitalization` が百万ドル、ROE・利益率・配当利回り・増収率は「％で表現済み」
(例 `roeTTM: 25.5` = 25.5%)、`totalDebt/totalEquity` は倍率。

LMT で照合したところ、株価 598.75 → 525.28 (**−12.27%**) に対し
時価総額 138B → 121.2B (**−12.17%**) と下落率が一致し、百万ドル単位であることを確認。
ROE 86.24 (手書き 78.0)、配当利回り 2.79 (2.35) も％表記で整合。

### 航空アフターマーケット / Aerospace Aftermarket

Tier-2の「Razor and Blades」型 IP保有者を探すためのカバレッジ（18銘柄）。剃刀（OEM出荷）ではなく替刃（スペア・修理）のannuityで企業を評価します。

**特化KPI**: アフターマーケット比率 / 自社IP・sole-source比率 / IP強度 / 型式証明の障壁 / アナリストカバレッジ / ビジネスモデル区分（A: IP保有・アフター主導、B: 受託製造、C: 独占アクセス権、C/D複合、素材、防衛電子、多角化）

**市場環境**: 搭載機数とフライト時間 / 型式証明の参入障壁 / 新造機の納入遅延 / PE・事業会社による再編 / 市場の分類ギャップ

**データ方針**: 株価・バリュエーション指標は `null`（未取得）。「🔄 最新に更新」でAPIから取得します。

## 適正価値の算出 / Fair value

添付フレームワーク 3.5「Reference Class Forecasting」/ 3.6「Relative P/E Multiple」の手法を実装しています（`valuation.js`）。

```
価格目標 = 1株あたり指標 × (ピア倍率 × 相対倍率)
```

### アウトサイド・ビュー（機械が担当）

同セクターのピア群を**レファレンス・クラス**として、PER・PBR・PSR の**中央値**を相対倍率 1.0 で当てます。「この銘柄はピア並みの評価に値する」という無色の出発点です。

資料の言葉どおり、ここは機械にやらせてよい領域です — *"We could almost let a computer do this ... it's important that we do this because it will remove some of the biases that naturally creep in"*

- ピアが **5銘柄未満**なら算出しません（レファレンス・クラスとして成立しないため）
- 赤字銘柄のPER等、成立しない倍率は**その手法だけ**除外します
- 3手法の結果の**中央値**を採用し、**最小〜最大の幅**も併記します

### インサイド・ビュー（あなたが担当）

`data.js` の銘柄に書きます。既定は両方 1.0 = 純粋なアウトサイド・ビュー。

```js
inside: {
  epsAdjust: 1.10,    // 収益力が実績比 +10% と見る
  relMultiple: 1.25,  // ピアに25%のプレミアムが妥当と見る
  note: { en: "...", ja: "根拠をここに書く" },
}
```

### 機械算出の判定は「暫定」扱い

**機械算出の適正価値に基づく判定は、緑/赤で確定表示しません。** 常に琥珀色の「暫定」です。
手書きの `fairValue` を置くと確定します。手書きがあれば機械は**絶対に上書きしません**。

### 方法の限界を隠さない

資料 3.3「Limitations of Multiples-Based Valuation Methods」への対応として、ピア倍率を当ててよいか怪しい場合に警告を出します。

| 検査 | 意味 |
|---|---|
| ROE・利益率がマイナス | 倍率法が成立しない領域 |
| ROE がピア中央値と大きく乖離 | PBR法が歪む（P/B は ROE で決まるため） |
| 純利益率が乖離 | PSR法が歪む |
| 増収率が乖離 | PER法が歪む |
| 手法間の算出値が1.5倍以上開く | どの手法もこの事業を説明できていない |

実例（航空アフターマーケット）:

- **TDG** は「回避 −33%」と出ますが、同時に *「ROE 37.1 はピア中央値 12.1 を大きく上回る → PBR法は実態より割高に見せる」* と警告します。質の高い複利成長企業がピア中央値モデルに罰せられている、という読み方をするための情報です。
- **DCO** は「買い +53%」と出ますが、*「ROEも純利益率もマイナス。倍率法が成立しない」*と警告します。安く見えるだけの罠です。

**警告が付いた判定は、判定ではなく問いだと考えてください。**

### 防衛セクター特化 / Defense specialization

防衛銘柄（LMT / RTX / NOC / GD）を選ぶと、以下が追加表示されます：

- **セクター市場環境** — 国防予算・地政学的緊張・売上見通し・予算リスク等を追い風/逆風で評価
- **特化KPI** — 受注/売上比率 (Book-to-Bill)、受注残高(年)、政府向け売上比率、海外比率、主力プログラム集中度
- **見るべきポイント解説** — 防衛セクター特有の着眼点

## 使い方 / How to run

ビルド不要。付属のローカルサーバーで起動します。

```bash
cd stock-analyzer
python3 serve.py
# ブラウザで http://localhost:8000 を開く
```

> `python3 -m http.server` でも閲覧はできますが、**スナップショット保存が使えません**（保存にはサーバー側の書き込みが必要なため）。`serve.py` で起動してください。

### スマホから見る / View on your phone

同じWi-Fiにつないだスマホから見るには、待ち受けアドレスを開放します。

```bash
cd stock-analyzer
python3 serve.py --host 0.0.0.0
```

起動時にスマホで開くURLが表示されます。

```
stock-analyzer: http://localhost:8000  (保存先 snapshot.js)
  LAN公開中: 同じWi-Fiの端末から http://192.168.x.x:8000 で開けます
  ※ スナップショット保存はこのMacからのみ。他端末からの書き込みは拒否します。
```

**既定は `127.0.0.1`（このMacのみ）です。** `--host 0.0.0.0` を付けたときだけLANに出ます。
その場合でも **`snapshot.js` への書き込みはこのMacからのリクエストに限定**され、
他端末からの `POST /api/save-snapshot` は 403 で拒否します（スマホからは閲覧のみ）。

> カフェや社内など、信頼できないネットワークでは `--host` を付けないでください。
> APIキーは各端末のブラウザ内(localStorage)に保存されるため、スマホで使うにはスマホ側でも入力が必要です。

## 取得データの保存 / Snapshot persistence

APIから取得した市場データはブラウザのメモリ上にしか無く、リロードで消えます。**「💾 スナップショット保存」**を押すと `snapshot.js` に書き出され、次回以降も保持されます（Gitに残るのでリサーチの記録にもなります）。

データは3層で重なります。上の層ほど優先されます。

| 層 | ファイル | 中身 | 更新者 |
|---|---|---|---|
| 3. 今セッションの取得値 | メモリ | 最新の市場データ | 🔄 最新に更新 |
| 2. 保存済みスナップショット | `snapshot.js` | 市場データ | 💾 保存（自動生成） |
| 1. 手書きの分析 | `data.js` | **適正価値・仮説・KPI・重要ファクター** | 人間 |

**`data.js` は機械が書き換えません。** 保存エンドポイントは株価・時価総額・バリュエーション指標のみを受け付け、それ以外のフィールド（`fairValue` や `thesis` 等）は破棄します。分析が上書きされる事故を防ぐためです。

## ローカル検証 / Local verification

APIもネットワークも使わず、macOS標準の JavaScriptCore だけで走る検証スクリプトです（node/deno不要・コスト0）。

```bash
cd stock-analyzer
./verify.sh
```

チェック内容：
- 閉じ括弧の重複（同一インデントの連続）と全ファイルの構文
- 全銘柄の必須フィールド・en/ja の欠落
- **データ方針の強制**: 株価が未取得(`null`)の銘柄に財務指標が入っていないか（＝推測値の混入検知）
- **未取得銘柄が投資判断を出していないか**（`recPending` で保留されているか）
- セクター定義の整合（KPIが参照するフィールドの存在、unitの妥当性、特化データブロックの有無）
- i18nキーの網羅（tag/i18n値・環境statusが両言語にあるか、ja/enのキー差分）
- フォーマッタの null 安全、メンター文脈が全銘柄で生成できるか
- **`snapshot.js` に手書きの分析が混入していないか**（各プロバイダが実際に返しうる項目に限定されているか）
- **手書きの適正価値が機械算出で上書きされていないか**／機械算出の判定がすべて暫定になっているか／ピア不足時に算出していないか

## データについて / About the data

現在は **サンプル（デモ）データ** を使用しています（`data.js`）。実際の市場データではありません。
データ構造は無料API（Financial Modeling Prep / Alpha Vantage 等）に差し替えやすい形にしてあります。
